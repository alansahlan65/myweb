# Domain docs

This project uses a single-context layout.

## Before exploring

Read root `CONTEXT.md` and relevant decisions in `docs/adr/`.

If those files are absent, proceed silently. Domain modeling creates them when terms or decisions are resolved.

## Vocabulary

Use domain terms as defined in `CONTEXT.md`, including in issues, proposals, and tests.

If a needed concept is missing, reconsider the terminology or note the gap for domain modeling.

## Decisions

Record decisions in `docs/adr/` with numbered filenames.

If a proposal contradicts an existing ADR, identify that ADR and explain why the decision should be reconsidered.
